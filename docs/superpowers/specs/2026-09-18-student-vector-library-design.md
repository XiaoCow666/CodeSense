# 学生向量库最小闭环设计

## 目标

为每名学生建立独立的学习记录向量索引，使用已完成提交反馈和知识点评分作为来源，让学生在首页看到索引状态，并让 Code Studio 的 AI 辅导在当前作业作用域内参考该学生自己的学习记录。

本轮成功指标：

- 已完成提交可以生成带来源、版本和学生作用域的索引记录。
- AI 查询只读取当前学生的 active 记录，并在作业编号存在时限制作业来源范围。
- 撤回或来源消失后，相关记录立即停止命中。
- 重建失败时保留上一版 active 索引，且可以通过学生首页再次重建。
- 离线评测可以复现 Recall@1、Recall@k、作用域过滤和撤回后的命中结果。
- 学生首页、教师知识覆盖和 AI 辅导三条角色路径都能返回可理解的下一步动作。

## 用户痛点与必要性

学生提交过多次代码后，AI 只能看到当前作业与当前问题，无法利用本人曾经出现的错误和反馈。教师可以看到班级知识覆盖，却缺少学生学习资料形成过程的可追溯索引。当前 `services/knowledge_vector_store.py` 每次请求创建临时索引，无法保存版本、撤回状态和检索日志。

当前时机来自两个条件：知识图谱第一阶段已提供作业、知识点和学生掌握度的受限投影；离线知识检索已经有稳定的 chunk、稀疏向量、回退和评测接口。把学生来源接入现有边界可以形成纵向闭环，维护成本低于引入外部向量服务。

替代方案包括继续使用请求级索引、直接引入外部向量服务、只显示结构化知识点。请求级索引无法支持生命周期，外部服务会增加凭据、部署和数据边界，结构化知识点无法覆盖提交反馈。当前采用数据库记录加本地稀疏向量，后续可以替换搜索实现而保留来源和权限模型。

## 数据模型

新增三个可回收表：

- `StudentLearningVector`：每条记录绑定 `student_id`、`scope_type`、`source_type`、`source_id`、`source_version`、`assignment_id`、脱敏文本、稀疏向量、`index_revision`、状态和时间字段。状态只允许 `active` 与 `revoked`。
- `StudentVectorIndexState`：每名学生一条当前索引状态，记录 revision、构建状态、来源数量、更新时间和失败代码。
- `StudentVectorRetrievalLog`：记录学生作用域、作业作用域、查询摘要哈希、返回数量、revision、检索模式和状态，不保存原始问题、代码或回答。

`db.create_all()` 的新增表创建沿用当前应用初始化方式。字段使用现有 SQLAlchemy 类型，SQLite 与 MySQL 均可创建。没有删除既有字段和历史数据。

## 来源与构建

`rebuild_student_vector_index(student_id)` 读取：

1. 当前学生已经评测完成的提交反馈和 AI 反馈，最多保留最近的有界数量，来源类型为 `submission_feedback`。
2. 当前学生自己的 `KnowledgePointScore`，来源类型为 `knowledge_point_score`。

索引文本只包含反馈与知识点评分摘要，不保存提交代码。文本经过现有 `KnowledgePrivacyFilter` 处理，向量由 `NgramCountEmbedder` 生成。`source_version` 由来源标识和规范化文本摘要生成，文本变化会生成新版本。

构建步骤在数据库事务中执行：先计算候选来源和向量，再把当前 active 记录更新到新 revision；已不存在的来源标记为 `revoked`，同版本记录复用，新增来源写入新记录。任意写入失败都会回滚事务，上一版 active 索引保持可用。

## 检索与权限

检索入口只接受当前登录学生的 `student_id`，服务层再次按 `StudentLearningVector.student_id` 过滤。作业查询存在时只允许当前作业来源和学生全局知识点评分来源；首页学习摘要可以读取当前学生全部来源。查询日志保存摘要哈希，不记录原文。

排序使用稀疏向量相似度，命中为空时返回可解释的 `no_result`。检索结果包含来源类型、来源编号、作业编号、revision、引用标题和有限长度文本。学生接口不返回其他学生编号、教师编号或内部数据库对象。教师端继续使用班级聚合图谱，不读取学生向量正文。

学生向量只作为 AI 辅导上下文和学习提示，不进入评分、能力分数、教师排名或高风险判断。AI 回答继续保留作业知识证据状态；个人学习记录作为单独的私有参考区展示。

## 产品入口

- 学生首页新增“我的学习记忆”面板，展示索引状态、来源数量、revision、更新时间和来源类别；未建立或失败时给出重建按钮与下一步说明。
- 每次正式提交评测完成后触发学生索引重建；重建失败不改变提交结果，状态在首页显示并支持再次重建。
- `/student/rebuild-learning-memory` 只允许当前学生执行，完成后回到首页。
- `POST /api/ask_question` 与 `POST /api/code_advice` 使用当前学生的受限检索结果生成上下文，并在 JSON/SSE 完成事件中返回私有学习记录收据。
- 教师仪表盘继续展示班级知识图谱聚合，验证教师只能看到自己可管理班级的汇总，不显示学生向量内容。

## 失败处理与回滚

- 没有索引：返回 `not_built`，AI 只使用当前作业知识和问题上下文。
- 没有命中：返回 `no_result`，AI 不声称参考了学生历史。
- 重建失败：返回 `failed`，保留上一版 active 记录，首页提供重建入口。
- 查询失败：返回 `unavailable`，AI 继续既有安全回答链路，记录低基数状态。
- 撤回来源：标记 `revoked` 后检索过滤；不删除审计记录。
- 回滚：恢复代码版本并执行一次 `rebuild_student_vector_index`；数据表可以保留，旧应用忽略新增表。

## 研究约束

- Lewis 等人的 RAG 论文说明外部非参数记忆可以补充模型生成，并强调来源可追溯与知识更新问题；本项目只将检索结果用作辅导上下文，不将其用于评分。
- Microsoft GraphRAG 文档把 Document、TextUnit、来源引用和查询上下文作为索引与查询边界；本项目保留来源、版本和作用域，暂不引入社区聚类与外部 LLM 索引。
- W3C WCAG 2.2 要求可感知、可操作、可理解和健壮；面板提供明确状态、可键盘操作按钮、状态文本和窄屏布局。

## 发布边界

新增表属于可回收的增量数据结构，发布前需要在隔离数据库完成创建、构建、查询、撤回和重建验证。生产发布仍需通过远端 main、`update.sh`、应用状态、`/healthz`、`/readyz`、受影响角色路径和对外发布材料门禁。若生产数据库无法确认新增表创建兼容性，候选保留在隔离分支并记录 `needs_human`。
