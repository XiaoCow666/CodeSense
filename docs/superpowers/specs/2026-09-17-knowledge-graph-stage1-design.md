# 知识图谱第一阶段：学习路径投影设计

## 目标

在不引入外部向量服务、不做生产数据库不可逆迁移的前提下，把 CodeSense 已有的作业知识点和学生知识点评分，投影成一个权限受控、能被学生和教师实际使用的学习知识图谱切片。

今天的交付不是“画一张图”，而是完成一条可验证的用户闭环：已有知识来源 → 图谱投影 → 学生/教师入口 → 下一步学习或教学动作 → 测试与真实走查。

## 当前事实

- 现有 [`models.py`](../../models.py) 已有 `AssignmentKnowledgePoint`：作业与知识点的显式关联，带权重、难度和来源标记。
- 现有 `KnowledgePointScore` 保存学生私有知识点评分、尝试次数、正确次数和更新时间；它不能作为跨学生检索内容。
- [`services/knowledge_rag.py`](../../services/knowledge_rag.py) 当前是作业范围内的显式证据检索，不是向量数据库，也没有图关系投影。
- 主工作区有 48 个已修改 tracked 文件和 2 个未跟踪文件，包含评分 0–5 到 0–100 的规范化、学生画像快照和题库操作；这些改动必须先在隔离候选中融合和回归，不能覆盖主工作区。
- 本地 `main` 起始于旧提交，远端 `origin/main` 已更新到 `52acab2`；候选以最新远端为基线。

## 用户闭环

### 学生

学生在已有首页/学习画像入口看到“我的知识路径”：

1. 当前作业涉及的知识点；
2. 自己的掌握度和最近练习信号；
3. 与当前知识点共同出现的相关知识点；
4. 可直接进入相关作业或 Code Studio 的下一步入口。

没有作业、没有评分或没有关系时，显示清晰的空状态和可执行的下一步，不伪造推荐。

### 教师

教师在已有教师首页/班级入口看到“班级知识覆盖”：

1. 当前授权班级的知识点覆盖；
2. 低掌握度且有足够样本的知识点；
3. 可回到相关作业、班级统计或学生详情的入口；
4. 样本不足、无数据和权限受限时的明确说明。

教师视图只返回授权班级的聚合数据；不能因为教师能看到一个作业，就扩展读取其他班级或学生私有资料。

## 图谱投影模型

第一阶段不新增持久化表，使用现有表生成受限读模型。所有关系都带 `relation_type`、`source`、`scope` 和可解释的权重。

| 节点/关系 | 含义 | 来源 | 可见范围 |
| --- | --- | --- | --- |
| `assignment` → `knowledge_point` / `covers` | 作业明确覆盖知识点 | `AssignmentKnowledgePoint` | 学生的已授权作业；教师的授权班级作业 |
| `student` → `knowledge_point` / `mastery` | 学生自己的掌握度 | `KnowledgePointScore` | 仅学生本人；教师只看授权班级聚合，不返回其他学生私有分数 |
| `knowledge_point` ↔ `knowledge_point` / `co_occurs` | 两知识点在同一作业中共同出现 | 同一作业的显式知识点关联 | 随当前作业/授权班级范围计算 |

`co_occurs` 明确标记为“共同出现推断”，不能在界面或 AI 文案中称为前置关系。第一阶段不做自然语言实体抽取、不把代码正文写入图谱、不引入未经评测的 embedding。

建议服务接口：

```python
build_student_learning_graph(
    *, student_id: str, assignment_id: int | None = None, limit: int = 8
) -> dict

build_teacher_knowledge_coverage(
    *, viewer_id: int, class_id: int | None = None, limit: int = 8
) -> dict
```

返回值固定包含：`nodes`、`edges`、`recommendations`、`meta`。`meta` 包含 `scope`、`source_revision`、`sample_size` 和 `is_inferred`，不包含代码、问题正文或跨作用域记录。

## 融合工作区改动

候选分支必须保留并审查主工作区的所有未提交变更：

- 评分规范化必须在模型、API、统计服务、模板和测试中统一使用 0–100，不能出现同一页面混用 0–5 和 0–100。
- 题库批量操作必须维持已有权限、CSRF、导出脱敏和空选择状态；它不是本阶段图谱关系的替代品，但不能因图谱开发回归。
- 教师学生快照必须与知识覆盖入口共存，避免重复查询、重复分页和不一致的学生状态。
- 任何冲突、未完成或无法证明真实收益的改动保留在候选审计中，不直接推送主工作区。

## 不做的事

- 今天不创建学生向量表、向量数据库、外部 embedding provider 或生产迁移。
- 今天不把 `KnowledgePointScore` 变成跨学生知识库。
- 今天不重写 Code Studio，不增加新的独立管理员质量卡片。
- 今天不把 co-occurrence 关系包装成教学真理；后续是否引入人工维护的前置/相关关系，要以真实评测和教师反馈决定。

## 验收标准

1. 候选工作树基于最新 `origin/main`，主工作区保持原样，未提交改动有融合清单和冲突结论。
2. 学生服务能在当前作业范围内返回自己的 mastery、覆盖知识点和共同出现关系；无数据时返回稳定空状态。
3. 教师服务只能返回授权班级聚合，样本不足时不误导为薄弱结论。
4. 学生首页/画像入口和教师首页/班级入口真正消费服务返回值，并提供可执行的作业/Code Studio/班级入口。
5. 测试覆盖数据边界、权限、旧评分兼容、空态、重复关系、关系上限和模板渲染；完整相关回归不因融合改动失败。
6. 使用 seeded demo 数据亲自走通学生和教师路径，检查桌面、窄屏、加载、空态、权限和返回后的状态；若体验断裂，先修复再计入完成。
7. 所有新增输出可回退：删除服务调用和模板挂载即可回到旧页面，不需要生产 schema 回滚。

## 研究约束

- WCAG 2.2 的可感知、可操作、可理解、可健壮原则用于验收入口、空态、键盘焦点和响应式；这是外部证据。
- RAG 与 Self-RAG 研究支持对来源和检索信号进行可追溯表达；针对 CodeSense 的推断是先建立来源可解释的图谱投影，再决定是否引入向量检索。
- 图谱关系的 `source/scope/is_inferred` 字段是本项目的安全设计约束，不声称来自上述研究的直接规定。
