# CodeSense 2026-09-18 运行报告：学生学习记忆与知识路径闭环

## 主方案与必要性

本轮主方案是把学生私有学习记忆接入评测结果、学生首页、学生提问和 Code Studio 代码辅导，并把知识图谱关系的来源与版本信息补齐。目标用户包括学生、教师和维护部署的管理员。

- 学生痛点：提交反馈和知识点记录分散在多个页面，学生很难知道哪些历史信息与当前作业相关。
- 教师痛点：知识路径需要可追溯关系来源，学生私有记录不能进入班级聚合。
- 管理员痛点：新增持久化数据需要随版本更新完成数据库维护，应用重启前需要有明确的维护顺序。
- 使用频率与影响范围：学生每次评测后、每次 AI 提问或代码辅导时都可能使用；教师在首页查看班级知识覆盖；管理员每次部署版本时执行维护流程。
- 成功指标：来源导入、受限检索、学生页面展示、AI 消费、来源撤回、失败重建、离线评测和部署维护全部有可重复证据；个人结果不会跨学生或班级返回。
- 依赖：现有评测反馈、KnowledgePointScore、作业权限检查、NgramCountEmbedder、现有 AI 路由、数据库维护脚本。
- 回滚方式：候选发布前保留现有版本；发布后重新部署上一份应用提交。新增学习记忆表采用新增结构，旧数据不会改变既有评分流程。

## 研究与设计约束

本轮查阅以下公开资料，并把资料中的可用原则转换为项目约束：

- Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks（Lewis 等，2020-05-22）：https://arxiv.org/abs/2005.11401 。检索内容需要进入生成流程，并且检索结果应可检查。项目约束是 AI 只消费当前学生、当前作业范围内的个人来源，并返回来源类型、作用域和索引版本。
- Microsoft GraphRAG：https://microsoft.github.io/graphrag/ 及默认数据流：https://microsoft.github.io/graphrag/index/default_dataflow/ 。图关系需要有结构化构建过程和来源信息。项目约束是每条新增图边保存来源引用和版本指纹，co_occurs 明确为同作业推断关系。
- WCAG 2.2：https://www.w3.org/TR/WCAG22/ 。状态、进度、焦点和可操作控件需要能被辅助技术理解。项目约束是学生首页使用语义状态文本、可读更新时间、按钮名称和权限提示。

资料结论用于约束可追溯检索、来源边界和交互状态；当前数据结构选择、学生作用域和重建方式属于结合 CodeSense 现有权限与数据库条件的项目推断，均由自动化测试覆盖。

## 独立交付清单

每个交付件均可单独验收，发布状态在部署门禁完成前统一记为候选。

1. 学生私有学习记忆数据模型。用户价值：保存学生来源、版本、作用域、索引修订号、撤回状态和重建状态。受影响端：数据库、学生学习服务、管理员维护。变更文件：models.py、services/student_vector_store.py。融合入口：评测反馈和 KnowledgePointScore 进入同一学生私有索引。验收证据：向量服务测试覆盖来源唯一性、状态和索引修订号。必要性：没有来源版本和作用域，个人学习记忆无法安全进入 AI 流程。回滚方式：重新部署上一份应用提交，新增表保留。

2. 评测反馈来源导入。用户价值：学生完成评测后可以把错误解释和改进建议用于后续复习。受影响端：提交评测、学生学习记忆、AI 辅导。变更文件：services/student_vector_store.py、tasks/submission_tasks.py、routes/api.py。融合入口：正式提交评测完成后刷新当前学生索引。验收证据：服务测试能够从提交反馈建立 active 来源。必要性：这是学生学习记忆的主要真实来源。回滚方式：停止刷新调用，保留既有评测结果。

3. 知识点记录来源导入。用户价值：学生的知识点掌握记录能够和历史反馈一起支持个性化引导。受影响端：学生画像、学习记忆、教师知识路径。变更文件：services/student_vector_store.py、tests/test_student_vector_store.py。融合入口：查询只返回当前学生的知识点来源。验收证据：来源类型、内容过滤和作用域断言通过。必要性：只有提交文本会遗漏结构化学习状态。回滚方式：停用知识点来源构建，反馈来源仍可用。

4. 权限先于召回的学生检索。用户价值：学生提问只会看到本人资料，当前作业请求还会收窄到作业相关来源。受影响端：学生端、AI 问答、Code Studio。变更文件：services/student_vector_store.py、tests/test_student_vector_store.py。融合入口：检索前按 student_id、student_private、active 状态和作业关系过滤。验收证据：离线评测覆盖跨学生隔离、作业范围和撤回过滤。必要性：个人学习记忆的隐私边界必须先于相似度计算。回滚方式：关闭个人检索调用，恢复公共知识检索。

5. 来源版本与持续撤回。用户价值：学生撤回某条学习来源后，未来重建也不会再次返回该来源。受影响端：学生首页、学习记忆服务、AI 检索。变更文件：services/student_vector_store.py、tests/test_student_vector_store.py。融合入口：每个来源身份保留版本，撤回状态跨新版本继续生效。验收证据：撤回后检索无命中，后续重建仍保持撤回。必要性：学习资料撤回需要可靠生命周期。回滚方式：恢复上一份索引修订号并停止新版本构建。

6. 失败重建保留上一份可用索引。用户价值：索引构建异常时学生仍能获得上一份学习引导，并能看到失败状态与重试入口。受影响端：学生首页、索引服务、任务日志。变更文件：services/student_vector_store.py、templates/components/student_learning_memory.html。融合入口：构建失败进入 failed 状态，上一份 active 来源保持可用。验收证据：失败重建测试检查 active 来源、失败状态和可重试条件。必要性：外部模型或数据库异常不能中断学生学习流程。回滚方式：继续使用上一份 active 修订号。

7. 检索审计与脱敏收据。用户价值：学生能够知道 AI 使用了哪些来源类别、作用域和索引版本，维护人员可以检查检索次数和结果数量。受影响端：学生 AI 页面、服务日志、质量评测。变更文件：services/student_vector_store.py、routes/api.py。融合入口：只记录查询摘要哈希和结果元数据，不记录原始查询文本；回答附加短收据。验收证据：问答与代码辅导测试检查收据字段和无原始来源标识。必要性：需要支持解释和诊断，同时降低日志中的个人内容暴露。回滚方式：关闭个人收据展示，保留匿名检索计数。

8. 评测任务自动刷新学生索引。用户价值：正式提交评测完成后，学生无需寻找数据入口就能获得最新学习记忆。受影响端：worker、提交结果、学生首页。变更文件：tasks/submission_tasks.py、tests/test_submission_worker.py。融合入口：worker 在提交事务完成后刷新当前学生索引，刷新失败保留提交结果并记录状态。验收证据：worker 测试检查评测完成、索引 ready 和反馈来源存在。必要性：自动刷新连接了评测与个人学习记忆。回滚方式：移除 worker 刷新调用，提交评测仍按原流程完成。

9. 同步提交路径自动刷新学生索引。用户价值：本地演示和同步提交路径与后台 worker 具有相同学习记忆行为。受影响端：提交 API、学生首页、AI 辅导。变更文件：routes/api.py、tests/test_student_vector_store.py。融合入口：提交事务提交后刷新当前学生索引。验收证据：同步提交测试和相关 AI 测试通过。必要性：避免不同提交入口形成学习数据断点。回滚方式：停用同步刷新，保留后台刷新。

10. 学生首页学习记忆状态与更新入口。用户价值：学生可以查看是否已建立、来源数量、更新时间、索引修订号和来源类型，也可以主动更新。受影响端：学生首页、窄屏布局、键盘操作。变更文件：routes/main.py、templates/student_home.html、templates/components/student_learning_memory.html、static/modern.css。融合入口：学习记忆卡片位于学生已有学习内容中，并链接到 POST 更新入口。验收证据：学生登录、空状态、失败状态、完成状态、更新操作和跨学生隔离测试通过。必要性：底层索引只有进入学生首页才构成可使用能力。回滚方式：隐藏卡片与更新入口，保留数据库来源。

11. 学生提问接入个人检索。用户价值：学生提问时可以得到基于本人历史反馈和当前作业的复习提示，并查看来源收据。受影响端：学生 AI 问答、SSE 响应、学习记忆服务。变更文件：routes/api.py、tests/test_knowledge_rag.py。融合入口：/api/ask_question 使用当前学生和当前作业约束检索。验收证据：同步与流式响应测试检查个人字段、公共知识字段和收据。必要性：把索引接入真实学习流程，避免孤立接口。回滚方式：回退到公共知识检索路径。

12. Code Studio 代码辅导接入个人检索。用户价值：学生在代码编辑器内请求建议时能够看到与本人历史错误相关的提示。受影响端：Code Studio、代码辅导 API、学生 AI 会话。变更文件：routes/api.py、tests/test_code_advice_knowledge.py。融合入口：/api/code_advice 使用问题或当前作业描述作为检索查询。验收证据：代码建议响应、分析响应和收据测试通过。必要性：学生最需要帮助的场景发生在代码提交与修正过程中。回滚方式：恢复公共知识提示，个人索引继续保留。

14. 知识图谱关系来源与版本。用户价值：学生知识路径和教师班级覆盖可以追踪关系来源，便于理解和后续重建。受影响端：学生图谱、教师图谱、AI 数据基础。变更文件：services/learning_graph.py、tests/test_learning_graph.py。融合入口：作业 covers、学生掌握度 mastery 和同作业 co_occurs 关系携带来源引用与版本指纹。验收证据：图谱边来源、版本、作用域和关系类型测试通过。必要性：图谱关系需要可解释的构建依据。回滚方式：回退到已有图谱关系生成，学生和教师页面保留原有节点。
